# Hive feed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hive apps publish a small status file in one envelope to the `hive` branch of `ndabney562/hivemind` and read each other's files through one Swift type and one CLI command; first link: HiveScore's top fix becomes a HiveTempo candidate.

**Architecture:** HiveMind owns writing (`hivemind feed publish`, git plumbing + lock, same pattern as `health_report.publish`). hive-kit owns the Swift types and reader. HiveScore scores on the Mac with its own Swift code (new `hivescore` executable) from the repo list the app sends to the hub. HiveTempo's planner publishes its summary and reads HiveScore's through the `hivemind` command.

**Tech Stack:** Python 3.9 stdlib (HiveMind, planner), Swift 6 packages (hive-kit, HealthScoreKit), launchd.

**Spec:** `hive-kit/docs/superpowers/specs/2026-11-08-hive-feed-design.md`

## Global Constraints

- Branch `hive` of `ndabney562/hivemind`; file name = `<app>.json` with `app` ∈ {`hivemind`, `hive-tempo`, `health-score`} for v1; validator accepts any `^[a-z0-9-]+$`.
- Envelope keys: `schema` (1), `app`, `written_at` (UTC `YYYY-MM-DDTHH:MM:SSZ`), `stale_after_minutes` (int > 0), `summary` (object), optional `detail` {`repo`, `branch`, `path`}.
- Max 64 KB per file. No secrets, tokens, prompts, answer text.
- Readers ignore unknown fields; skip unknown `schema`; missing file → nil/absent, never an error.
- Phones never write to GitHub. Tokens never written to files.
- Tests: each repo's PROJECT.md test command; `zsh ~/agent-rules/scripts/hive-test-all.sh` before the last merge.
- Commits on feature branches, one PR per repo; Codex review per rule 9 (`--risk high` for Tasks 3–5: token and pairing).

## Review Focus

1. Two Mac jobs publish in the same second → lock serialises; a rejected push is retried on the new tip (Task 2 test `test_rejected_push_retries_on_new_tip`).
2. Feed file present but from yesterday → shown as stale, never as current; planner adds no fix (Tasks 1, 2, 6 stale tests).
3. HiveScore app never paired, or paired to an old hub without the endpoint (404) → settings save still works, no error shown (Task 5 test `test404IsIgnored`).
4. `gh auth token` missing or expired → the wrapper exits non-zero without publishing; the old file ages into stale (Task 4 wrapper test).
5. Repo list from the phone contains an unknown or malformed entry → hub rejects with 400 and keeps the old file (Task 3 test).
